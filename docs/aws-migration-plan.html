Team Hub AWS Migration

How the club hub moves from claude.ai to your own AWS account: an AWS SAM stack, email-and-password sign-in with Cognito, a role-checking API over DynamoDB, and live updates pushed over WebSockets, all deployed from GitHub.

01

Decisions

InfrastructureAWS SAM

One template.yaml for the whole stack; sam build bundles TypeScript with esbuild; samconfig.toml holds dev and prod.

Sign-inEmail + password

Cognito user pool with email as the username, verified email, and self sign-up limited to invited addresses.

Live updatesWebSocket push

DynamoDB Streams notify a fan-out function, which tells every open browser on that team what changed.

Carried overSingle-table DynamoDB

The TeamHub key design from teamhub-dynamodb/, now defined in SAM, plus two new item types for invites and connections.

02

Architecture

The browser talks to four AWS front doors: CloudFront for the page, Cognito to sign in, the HTTP API to read and write, and the WebSocket API to hear about changes. Only the API function writes team data, so every role rule is enforced on the server.

03

SAM stack

Two stacks. A one-time bootstrap stack creates the GitHub OIDC trust and deploy roles. The app stack (template.yaml) holds everything else and is deployed once per environment.

If you already ran create-table.sh, bring that table into the stack with a CloudFormation resource import instead of creating a second one. Outputs (UserPoolId, ClientId, ApiUrl, WsUrl, SiteBucket, DistributionId) feed the site's config.json at deploy time.

04

Sign-in

Email and password, with invitations standing in for today's "Link my account" approvals. Coaches and admins invite people by email with a role and family already attached, so a parent is ready to go the moment they verify their email.

StepWhat happensData
1. InviteAn admin invites an email to a team (the roster emails can be bulk-invited)INVITE#email / TEAM#t with person, pid, roles
2. Sign upThe person opens the site, enters that email and a password. The pre-sign-up check refuses emails with no invite.Cognito user created, unconfirmed
3. VerifyCognito emails a 6-digit code, and the person enters it—
4. LinkThe post-confirmation trigger turns each invite into a membership and deletes the inviteMEMBER#sub + GSI1 USER#sub
5. SessionsThe page keeps tokens in memory and renews them with the refresh token; "Forgot password" uses Cognito's reset code—

People already approved on claude.ai become invites during migration, so nobody waits for a second approval. Roles live only in DynamoDB, never in Cognito groups, so role changes take effect on the next API call without a new sign-in.

05

API contract

All routes require a valid token. The router loads the caller's MEMBER#sub item for the team and checks it against a permissions.ts module that the page also imports, so the server and the screens share one role table.

RouteWhoDynamoDB
GET /meAnyone signed inQuery GSI1 USER#sub → teams and roles; get club-admin flag
GET /teams · POST /teamsAll · club adminQuery CLUB#c · put team, settings and handbook in one transaction
GET /teams/{t}MembersQuery TEAM#t, trimmed by role (contacts and ledger only for permitted roles)
PUT /teams/{t}/settings · /handbookCoordinator, admin, coach (handbook)Put META#…
PUT/DEL /teams/{t}/players/{pid}Coordinator, adminPlayer + contacts items
PUT/DEL /teams/{t}/events/{eid}Coach, coordinator, adminEVENT#eid with GSI2 calendar keys
PUT /teams/{t}/events/{eid}/refjobs · /agendaCoach, coordinator (agenda also food)EVENT#eid#REFJOBS · #AGENDA
PUT/DEL /teams/{t}/meals/{mid}Food, coordinator, adminEVENT#eid#MEAL#mid
POST /teams/{t}/meals/{mid}/claim · DEL sameParent (own family)Conditional update: attribute_not_exists(claimedBy)
PUT /teams/{t}/family/{pid}Parent of pid; coach/coordinator for RSVPsUpdate USER#sub / FAMILY#t map paths
GET /teams/{t}/familyMembersQuery GSI1 TEAM#t FAMILY#; server merges newest answer per player
POST /teams/{t}/payments · DEL /payments/{id}Parent; any member for reimbursementsUSER#sub / PAYMENT#t#id, status pending
POST /teams/{t}/payments/{uid}/{id}/confirm · /declineFinance, coordinator, adminTransaction: put LEDGER# if absent + update payment status and GSI1SK

PUT/DEL /teams/{t}/announcements/{id} · /tasks/{id}Coach, coordinator · coordinatorANN# · TASK#

PUT/DEL /teams/{t}/members/{sub}Team admin, club adminMEMBER#sub; the server refuses to remove the last admin

Role approval moves from "site owner only" to team admins and club admins. The server enforces it, so it no longer needs to rest on a single owner.

06

WebSocket push

Pushes carry what changed, never the data itself. The browser then re-reads through the API, so someone without permission to see the ledger never receives ledger numbers over the socket.

Connection itemValue
KeyPK=TEAM#t, SK=CONN#connId
Reverse lookupGSI1PK=CONN#connId (clean-up on disconnect)
Fieldstype=Connection, sub, connectedAt
Expiryttl = now + 3 h (connections last at most 2 h)
Client ruleWhy
Send ping every 5 minAPI Gateway drops idle sockets after 10 min
Reconnect with backoff (1s → 30s)Sockets end at 2 h, on network change, or on deploy
Re-subscribe on team switchOne team per connection keeps fan-out simple
Refetch everything after a reconnectNotices sent while offline are not replayed
Coalesce notices for 300 msA ref-job rotation fires many writes at once
07

Front end

The screens stay as they are. Four modules replace what claude.ai used to provide:

ModuleReplacesDoes
auth.tsclaude.use("user")Sign-up, verify-code, sign-in, forgot-password screens; token refresh (via aws-amplify/auth)
api.tsdb.doc().set/deleteTyped fetch wrapper adding the token; maps each current save() call to its route
store.tsdb.collection().onSnapshotLoads a team once, holds the S state the screens already read, and refetches a collection when a push arrives
realtime.tsPlatform live syncWebSocket connect, subscribe, ping, reconnect

Build with Vite: the current single HTML file is split into modules, TypeScript is added gradually, and hashed assets are cached for a year at CloudFront. The Access tab becomes Invites & Members. Everything else keeps its current layout.

Phases

01–2 days

Foundation

  • Create GitHub repo, branch protection, dev and prod environments
  • Deploy the bootstrap stack (OIDC provider, deploy roles)
  • SAM skeleton: table, bucket, CloudFront, placeholder page; CI and deploy workflows
Done when a merge to main deploys a page to the dev CloudFront URL with no manual steps.
12 days

Sign-in

  • User pool, client, SES sender identity and production-access request
  • Pre-sign-up and post-confirmation triggers with the invite model
  • Sign-up, verify, sign-in and reset screens
Done when an invited email can sign up, verify and land on the hub; an uninvited email is refused.
24–5 days

API

  • Router, shared permissions.ts, key builders
  • All routes in the API contract, with transactions for confirm, approve and claim
  • Tests per route and role against DynamoDB Local
Done when each route passes the role matrix tests (allowed roles succeed, others get 403).
32–3 days

WebSocket push

  • WebSocket API, authorizer, connect, disconnect and subscribe functions
  • Fan-out with stream filter, GoneException clean-up, and alarms
  • Client realtime.ts with ping, reconnect and coalescing
Done when a change in one browser shows in another within 2 seconds, and a dropped connection recovers by itself.
43–4 days

Front end on the API

  • Vite build; split the page into modules; auth, api, store
  • Replace every save() and onSnapshot with API and push equivalents
  • Access tab becomes Invites & Members
Done when every screen works on dev for each role (coach, coordinator, food, finance, parent).
52 days

Migration & user testing

  • Export, transform, dry run, load into dev
  • Coaches, the coordinator and two parents test on dev
  • Fix-up pass
Done when record counts match the export and testers sign off.
61 day

Cutover

  • Freeze the claude.ai hub, final export, load into prod
  • Domain and certificate live; send invites to the roster
  • Old hub shows a "we've moved" banner
Done when most families have signed in within a week, with no data lost.

Risks

RiskMitigation
Cognito's built-in email sends only a few messages a dayConfigure SES and request production access in Phase 1, since approval can take a day
Parents don't finish sign-upPre-approved invites, clear verification email copy, and a coordinator view of who hasn't joined
WebSocket drops (2 h limit, 10 min idle, phone sleep)Ping, backoff reconnect, full refetch on reconnect
Fan-out loops on its own connection writesStream event filter excludes type = Connection
A stale connection blocks fan-outDelete the connection on GoneException; TTL removes the rest
Cold starts slow the first clickarm64, esbuild bundles, minimal dependencies (typically well under a second)
Deploy mistakes reach prodProd behind an approval environment; DeletionPolicy: Retain on the table and user pool
Data drift during cutoverFreeze edits, then compare counts per type before and after
